- **2026-06-22** **RSVP declined-count drift fix: guests no longer auto-declined on games (dev + prod).** Symptom: the game card/detail RSVP "bricks" (`ParticipationSummary`) showed e.g. **2 declined** while the roster modal showed **1** — on most/all games of any team carrying a guest with a standing absence (e.g. H3 game 509 `vb_406201`: Alex Leonhardt, `guest_level=1`, auto-declined). Root cause: `autoDeclineForAbsence` (kscw-hooks) inserted a `declined` GAME row for **any** member on the team, missing the `mt.guest_level = 0` guard the auto-**confirm** path has. Guests can never play league games (`trg_participations_guest_block` + UI hide RSVP), and the roster modal already excludes them — but `ParticipationSummary` counts every participation row regardless of roster membership, so each guest row pushed the declined tally one above the roster. **Fix**: added `AND mt.guest_level = 0` to the games auto-decline INSERT (mirrors auto-confirm). **Migration 124** (idempotent data cleanup) deletes historical guest game auto-decline rows — **96 rows** on both dev + prod (7 guests across teams). Also moved the **"Show roster" button** in `GameDetailModal` from the buried bottom "Participation details" section to directly beneath the RSVP tallies (visible for any scheduled game; old section now self-hides when it has no deadline/coach content). Deploy: `ext:deploy:{dev,prod}` (hook first → no new noise) → `db:migrate:{dev,prod}` (124) → frontend push. Verified post-migration: 0 remaining guest game rows, game 509 declined = 1. Build green; eslint errors in `GameDetailModal` are pre-existing (`set-state-in-effect`/`refs`, not in touched code). No perm change, no version bump.
