- **2026-06-21** **Scorer official-contact visibility for coaches/TR (dev only, extension + frontend).** Assigned scorer/official email+phone was shown only to sport admins. Coaches and team-responsibles now see the contact of officials assigned to games **their team holds the scorekeeping duty for — and only those** (the user's "only for that game" requirement). Enforced server-side by a new scoped read endpoint, **not** a Directus permission row (a per-game contact filter would walk games→members through a policy = the documented "deep filter + policy walk → silent empty" trap). `GET /kscw/scorer/official-contacts` (`directus/extensions/kscw-endpoints/src/scorer-contacts.js`, wired in `index.js`): resolves the caller's coached/TR teams (`teams_coaches`/`teams_responsibles`), finds `type='home'` games where one of those teams owns a specific duty role, and returns `phone`/`email`/`hide_*` for just that role's assigned official (incl. delegated cross-team officials a coach can't read via the items API). No led teams → `{}`; raw-knex read with authz in code, so coaches still can't bulk-read member contacts through the items API; read-only ⇒ no audit/actor capture. Frontend: `useOfficialContacts()` fetches the scoped map (skipped for admins — items-API already — and non-leaders), merges it onto member objects so `AssignmentEditor` renders it (still respecting `hide_phone`/`hide_email`); `showContact` now true for leaders; duty-game visibility widened to coached/TR teams so a **staff-only** coach (not a roster member) also sees their team's duty games. `npm run build` (tsc -b) green; eslint clean on new code; endpoint live-checked (`401 {"error":"Authentication required"}` unauth). **No schema/permission change** (so no migration, no `setup-permissions.mjs` edit). **dev**: `372bb57c` pushed (frontend CF Pages auto-deploy) + `npm run ext:deploy:dev` (directus-kscw-dev restarted, smoke ✓). **prod**: promoted same day — cherry-pick `372bb57c` → prod `635c1ffc`, pushed (CF Pages auto-deploy) + `npm run ext:deploy:prod` (directus-kscw restarted, smoke ✓); prod endpoint live-checked (`401` unauth).

- **2026-06-20** **Minor-protection: no under-18 PII leaves the public API (dev + prod).** Audit found the unauthenticated `GET /kscw/public/team/:id` (`directus/extensions/kscw-endpoints/src/index.js`) returned the **full roster of any team by id with no age filter** — leaking the first names (+ team/age-band, #/position) of ~100 children on the youth teams (U18/U16/U14/U12, Mini) to anyone hitting the URL, even though the website never rendered those pages (BB youth `hasDetailPage:false`; only VB U23/U20 + seniors render rosters). Privacy flags mitigated the worst (yob suppressed via `birthdate_visibility` default hidden, photos via `website_visible` default false, surnames → initial) but full first names + roster membership still left the server. **Fix (3 layers):** (1) endpoint now returns **no roster** for teams underage-by-definition (name `U≤18` or Mini) and **age-filters every other team** by birthdate (`<18` dropped; missing/unparseable birthdate ⇒ treated as minor & hidden — "prove adult or hide"); coaches kept; game-card officials gated by the same age rule (youth scorers no longer named). (2) `setup-permissions.mjs` public `/items/members` read now `_and(website_visible=true, birthdate ≤ $NOW(-18 years))` so an under-18 can never return even if `website_visible` is mistakenly set. (3) **ClubDesk birthdate backfill** — the "hide if no birthdate" rule initially emptied basketball senior rosters (BB had ~no birthdates in `members`); ClubDesk staging (`clubdesk_export.geburtsdatum`, 97% populated) was the source of truth, so backfilled `members.birthdate` from it (NULLs only, licence-then-email match + first-name safeguard, dd.mm.yyyy→ISO) via the Directus API: **246 patched, 0 errors, 0 ambiguous**. Prod after: 348 adults shown (was 148), 120 real minors correctly hidden, 22 rows still birthdate-less (stay hidden per decision). Verified live on prod across youth/U23/senior teams — youth rosters empty, minors stripped, no yob leak, BB seniors restored. Committed `8a48153b` on dev; backend via `ext:deploy:dev`+`ext:deploy:prod`; perms via `db:setup-perms:dev`+`:prod` (477 perms, 0 errors). No frontend/changelog change (website just receives less data). **Follow-up:** make the birthdate backfill part of the weekly ClubDesk sync so new members don't regress to hidden (privacy stays safe-by-default regardless — missing birthdate hides, not exposes).

Validated the new sync path locally against the live API (134 rows, all keyed on the triple, all labelled 2025/26). Bump `1.1.0` → `1.2.0` + CHANGELOG/ChangelogPage.
